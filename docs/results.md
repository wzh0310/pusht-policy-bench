# 评测方法与结果

## 设置

| 项目 | 值 |
|---|---|
| 策略 | `lerobot/diffusion_pusht`（Diffusion Policy，图像 + 2D 状态输入） |
| 环境 | `gym_pusht` 的 `PushT-v0`，10 fps，episode 上限 300 步 |
| Episodes | 10 |
| 渲染 | 离屏（`MUJOCO_GL=egl`），逐 episode 导出 mp4 |
| 硬件 | RTX A6000 / driver 550.107.02 / CUDA 12.6 |
| 软件 | PyTorch 2.7.1+cu126 / LeRobot 0.7.1 / Python 3.12 |

复现命令即 `bash scripts/eval_pusht.sh`，随机种子由 LeRobot 评测入口统一控制。

观察：累计奖励与成功率不成正比。第 8 个 episode 累计奖励 122.64，是全部样本中最高之一，却因为始终没能把覆盖率推过阈值而失败——它在接近成功的位置反复调整，耗时最长。这说明 PushT 的稀疏判定（覆盖率阈值）与密集奖励（累计覆盖率）评估的是不同维度。

## 失败案例分析

第 8 个 episode 的录像见 `assets/demo_failure.mp4`。

- 末帧覆盖率 0.626，说明 T 形块已进入目标区附近但角度未对齐
- 累计奖励偏高，表明夹爪长时间在目标区域内小幅修正
- 典型失败模式：**接近成功后的过度修正**，而非完全找不到目标

这类失败对策略的启示：单步位置回归无法表达"先旋转再推入"的复合动作，需要更长的动作块或更高的观测频率。

## 指标口径说明

- `sum_reward`：整个 episode 中每一步覆盖率的累加，受 episode 长度影响
- `max_reward`：episode 内达到的最高覆盖率
- `success`：覆盖率首次超过阈值的时刻被标记，阈值由环境定义
- 置信区间使用 Wilson 区间，样本量 10 时区间必然很宽；若要报告可信成功率，建议至少 50 个 episode

## 耗时构成

单 episode 5.08 s 中包含三部分：

1. MuJoCo 物理步进与离屏渲染
2. 策略前向（Diffusion Policy 需要多次去噪迭代）
3. 视频编码写入

若只需成功率而不需要录像，可关闭视频导出，耗时主要降在第三项。
